REVISI MAGANG: PEMBIMBING TUNGGAL = DOSEN PA
=============================================
Pembimbing 1 & 2 ditiadakan. Satu-satunya pembimbing magang adalah Dosen PA
mahasiswa (users.dosenPaId). Dosen PA: menyetujui/menolak/mengunci logbook,
mengisi Nilai Logbook, meninjau/ACC laporan, mengisi Nilai Laporan, mengelola
periode magang. Koleksi `bimbingan` tidak dibaca/ditulis lagi (data dibiarkan).

CARA PASANG
-----------
Timpa file-file di zip ini ke proyek (struktur folder sama). Satu file baru:
helpers/pembimbingHelper.js.

CETAK LOGBOOK SERAGAM (mahasiswa = dosen = admin)
-------------------------------------------------
Semua cetak logbook sekarang memakai SATU template: views/mahasiswa/magang/print.ejs,
dengan data dari helpers/logbookPrintHelper.js (file baru, buildLogbookPrintData).
 - Mahasiswa : /mahasiswa/magang/logbook-print?periodId=...   (hanya miliknya sendiri)
 - Dosen PA  : /dosen/magang/print/:userId?periodId=...        (hanya mahasiswa PA-nya)
 - Admin     : /admin/emagang/print?userId=...&periodId=...    (userId wajib)
Perbedaan antar peran hanya pada pengecekan hak akses.
HAPUS file lama yang sudah tidak dipakai (zip tidak bisa membawa penghapusan):
   views/dosen/magang_print.ejs
   views/admin/emagang_print.ejs
Catatan: cetak admin dulu bisa mencetak SEMUA mahasiswa sekaligus (tanpa userId).
Fitur itu dihapus karena tidak ada tombol yang memakainya dan template mahasiswa
dibuat per mahasiswa; tanpa userId kini muncul pesan "Pilih mahasiswa dulu".
Fungsi bantu cetak (progress, rekap mingguan, daftar hadir, kode validasi, dll.)
dipindah dari routes/mahasiswa/magang.js ke helpers/logbookPrintHelper.js.

MAHASISWA CUTI / KELUAR TIDAK DIIKUTKAN (e-learning, magang, cetak)
--------------------------------------------------------------------
Helper baru: helpers/statusMahasiswaHelper.js (status 'Cuti' dan 'Keluar').
Prinsip: FILTER SAAT MEMBACA - data enrollment/nilai/logbook TIDAK diubah atau
dihapus, jadi kalau status dikembalikan ke 'Aktif' mahasiswa muncul lagi.
Status 'Lulus' TIDAK dikecualikan. Status dibaca dari cache mahasiswa (10 menit,
otomatis dibersihkan saat admin mengubah data mahasiswa) -> tanpa read tambahan.
Dipasang di:
 - Peserta kelas E-Learning: dosen/mk.js (peserta, absensi/nilai, detail, LKM +
   jumlah mahasiswa), dosen/mahasiswa.js, dosen/nilai.js, dosen/index.js (tugas),
   dosen/kurikulum.js, dosen/rubrik.js, admin/rubrik.js, admin/nilai.js,
   helpers/kelasChatHelper.js (peserta chat kelas)
 - Magang: admin/emagang.js (daftar magang), admin/surat.js (daftar undangan
   seminar), helpers/magangHelper.js (PDK mahasiswa Cuti/Keluar = kosong, jadi
   tidak bisa membuat periode/logbook)
 - Cetak: admin/mahasiswa.js /print (Cuti/Keluar tidak dicetak kecuali admin
   memilih filter Status Mahasiswa). SK PA sudah dibatasi 'Aktif' sejak awal.
Belum disentuh (sengaja): halaman e-learning sisi MAHASISWA itu sendiri (kalau
mahasiswa Cuti/Keluar login, ia masih bisa membuka kelas yang sudah ia ambil),
dan halaman admin yang memang menampilkan SEMUA mahasiswa (daftar, tagihan, dll).

HALAMAN "MAHASISWA PA" (/dosen/mahasiswa-pa) = PUSAT KERJA DOSEN PA
------------------------------------------------------------------
Ringkasan (total, sedang magang, logbook menunggu, laporan belum ditinjau),
filter status (Aktif/Cuti/Keluar/Lulus) + "Perlu Ditindak" + cari nama/NIM,
kolom Magang & Menunggu Anda, tombol Logbook / Laporan / Cetak tiap mahasiswa.
Mahasiswa Cuti/Keluar tetap tampil tapi tanpa info magang dan tombol aksi.
File: routes/dosen/mahasiswaPa.js, views/dosen/mahasiswa_pa.ejs.

LEMBAR KONSULTASI BIMBINGAN AKADEMIK
------------------------------------
Dosen PA mencatat tiap pertemuan konsultasi per mahasiswa; mahasiswa melihat &
mencetak (read-only). Koleksi Firestore BARU: `konsultasiPa` (satu dokumen per
pertemuan: mahasiswaId, dosenId, dosenNama, tanggal, kategori, topik, uraian,
saran, semester, createdAt, updatedAt). Query hanya 1 filter (mahasiswaId) ->
TIDAK butuh composite index baru.
 - Dosen     : /dosen/mahasiswa-pa  (tombol Konsultasi)
               /dosen/mahasiswa-pa/:id/konsultasi (catat/ubah/hapus) dan /print
 - Mahasiswa : /mahasiswa/konsultasi-pa dan /mahasiswa/konsultasi-pa/print
               (kartu "Konsultasi PA" di dashboard mahasiswa)
 - Cetak dosen & mahasiswa memakai SATU template: views/konsultasi_pa_print.ejs
   (kop, identitas, tabel + kolom paraf, minimal 10 baris, TTD mahasiswa & Dosen PA)
File baru: helpers/konsultasiPaHelper.js, routes/mahasiswa/konsultasiPa.js,
views/dosen/konsultasi_pa.ejs, views/mahasiswa/konsultasi_pa.ejs,
views/konsultasi_pa_print.ejs. Yang diubah: routes/dosen/mahasiswaPa.js,
views/dosen/mahasiswa_pa.ejs, routes/mahasiswa/index.js, views/mahasiswa/dashboard.ejs.

PERLU DICEK SETELAH PASANG
--------------------------
1. Mahasiswa tanpa dosenPaId TIDAK bisa isi logbook / upload laporan.
   Cek di /admin/bimbingan (sekarang halaman baca-saja) dan tetapkan Dosen PA.
2. Data lama (logbook/laporan/periode yang menyimpan pembimbing1Id/2Id) tidak
   dimigrasi. Periode lama masih terbaca di beberapa view lewat fallback
   pembimbing1Nama, tapi hak akses SELALU berdasarkan Dosen PA saat ini.
3. Surat undangan seminar sekarang 3 rangkap (Dosen PA, Wadir I, PPMA).
4. Masukan logbook mingguan: view cetak membaca tipe 'pembimbing' (baru) dan
   'pembimbing1'/'pembimbing2' (lama). Kode penulis masukan (routes/pembimbing/
   logbookMasukan.js) TIDAK ada di zip - kalau ada, ubah tipe yang ditulis
   menjadi 'pembimbing'.
5. File di root (magang1.js, display.js, landing.js, index.ejs, print.ejs)
   tidak dipakai app.js dan tidak disentuh.
6. Sudah dicek: semua JS lolos node --check, semua EJS yang diubah lolos
   kompilasi, dan alur cetak (build data + render print.ejs) lolos uji dengan
   Firestore tiruan. BELUM diuji dengan Firestore asli / tampilan di browser.
